# P6.2 — формальная постановка задачи

## 1. Возможные постановки

| постановка | подходит? | почему |
|---|---|---|
| POMDP (Kaelbling, Littman & Cassandra 1998) | **да, как базовая модель** | скрытое состояние эпизода, наблюдения раскрываются действиями, итоговая награда |
| Контекстная задача решения (один контекст, одна выплата) | частично | эпизод — контекст, выплата одна, но решения последовательные |
| Последовательный сбор информации | **да, для фазы проверки** | каждое действие, кроме submit, покупает информацию по фиксированной цене и никогда не меняет мир |
| Среда для агента с инструментами (ср. ReAct, WebShop) | да, описательно | действия — типизированные вызовы инструментов с аргументами; выходы — структурированные документы |
| Иерархическая задача (options; Sutton, Precup & Singh 1999) | **да, для проектирования политики** | «обойти таблицу» — естественная многошаговая опция; отправка ответа — отдельное структурированное решение |

Вывод: моделировать Ophanim как **POMDP с конечным горизонтом, статичным скрытым состоянием,
детерминированными переходами и наблюдениями и единственным завершающим структурированным действием со
значением-множеством**, а решать иерархически: (i) процесс сбора информации над знаниями, которые агент уже
раскрыл, затем (ii) структурное предсказание при отправке.

## 2. POMDP M = (S, A, O, T, Z, R, γ)

| элемент | определение | явно ли в коде? |
|---|---|---|
| **S** | `s_t = (W, D, t, τ, done)`: скрытый мир `W` (эталон `Y*`, provenance, генерация с секретным ключом), публичный набор данных `D` (манифест, политика, четыре таблицы), счётчик шагов `t`, прошедшее время `τ`, флаг завершения | `W`/`D` = `SealedEpisode`/`PublicEpisode` (`generator/episode.py` L53, L77); `t`, `τ`, `done` = `_EpisodeState` (`env/environment.py` L54) |
| **s₀ ~ ρ** | `ρ(seed, config, secret)` = генератор | `generate_episode` (`generator/episode.py` L170) |
| **A** | `A = A_list ∪ A_get ∪ A_doc ∪ A_calc ∪ A_submit ∪ A_invalid`, каждое — параметризованное семейство (см. §4) | `schemas.py` L123–L152 |
| **T** | детерминированный: `t ← t+1`; `done ← true` при submit, или `t = 100`, или `τ > 60 с`; `W, D` никогда не меняются | `step` L109 |
| **O, Z** | `o_t = Z(D, a_t, t)`: вывод инструмента на `D` или код ошибки, плюс `100 − t`; детерминированно | `Toolbox` (`env/tools.py`); словарь наблюдения L126 |
| **R** | `r_t = 0` до завершения; `r_T = clip(2·F1(F, Y*) − 1 − 0.002·k, −1, 1)`; неверная структура `F` → −1; обрыв → `F = ∅` | `evaluator/reward.py` L44, `judge.py` |
| **γ** | 1 (конечный горизонт H = 100; доход за эпизод = итоговая награда) | концептуально |

Концептуальные абстракции (не объекты кода): состояние убеждений, ценность сбора информации и разложение
из §3. Часы находятся вне MDP: это условие обрыва, что соответствует определению `truncated` в Gymnasium.

## 3. Структурные свойства (с доказательствами)

**P1 — Статичное состояние и детерминированные наблюдения ⇒ раскрытое множество — достаточная
статистика.** Поскольку `D` фиксирован, а `Z` детерминирован, апостериорное распределение по `D` при
истории `h_t` зависит только от множества уже раскрытых записей `K_t ⊆ D`. Повтор действия ничего нового
не раскрывает. Агент, который явно хранит `K_t` (хранилище записей по ключу), не теряет информации по
сравнению с полной историей; рекуррентность не *нужна* для оптимальности, она нужна только агентам без
явной памяти.

**P2 — Ответ — функция публичных данных.** Для каждого сгенерированного эпизода независимый аудитор
(`audit/reconcile.py`, не импортирующий код генератора) точно воспроизводит эталон: 108 эпизодов в наборе
тестов и 20/20 в закрытом наборе (`runs/verify/report.json`, проверки данных). Значит, `Y* = g(D)`, где
`g` — опубликованная политика: неопределённость чисто **эпистемическая** (какие записи ещё не прочитаны) и
никогда не алеаторная. Как только `D` раскрыт, оптимальный ответ определён.

**P3 — Разложение и запас.** Пусть `C(D)` — число шагов, которое стратегия тратит, чтобы раскрыть
достаточно `D` для определения `Y*`. Агент, который читает, пока `Y*` не станет определённым, а затем
отправляет `g(K)`, получает `E[1 − 0.002·C(D)]`. Поскольку награда никогда не превышает 1, любая стратегия
сбора информации может улучшить полный обход не больше чем на стоимость самого полного обхода. Полный
обход раскрывает всё; измеренная стоимость полного обхода — 12–22 шага на эпизодах medium
(`p6_repository_audit.md`, §9). Поэтому **максимальный выигрыш от более умного сбора информации по
сравнению с полным обходом — не больше 0.002 × (шаги полного обхода) ≈ 0.024–0.044 на эпизод medium**,
тогда как ошибки в ответе двигают награду в масштабе 2.0.

**P4 — Подтверждение отсутствия требует (почти) полного чтения.** Чтобы отправить «дублей нет / ошибок
распределения нет», агент должен прочитать каждую относящуюся к делу проводку и документ; отрицательное
доказательство нельзя получить выборкой. Поэтому чистые эпизоды тоже требуют почти полного обхода, чтобы
пустой ответ был верным *и обоснованным*.

**P5 — Ровное плато неудачи.** Если F1 = 0, то `2·0 − 1 − 0.002k ≤ −1`, поэтому награда ровно −1 для
*любого* поведения без true positive. Измерено: случайный исследователь получил ровно −1.0 на всех 15
закрытых эпизодах с ошибками. Для обучения методом градиента политики это означает нулевую дисперсию
дохода, а значит, нулевой сигнал преимущества на эпизодах с ошибками, пока не найден первый true positive.

**P6 — Вырожденный аттрактор.** Среди политик, которые не умеют находить ошибки, «сразу ничего не
отправлять» даёт `2·p_clean − 1` (−0.5 на закрытом наборе, измерено). Это предсказанный локальный оптимум
для любого обучаемого агента, выводы которого ещё неточны; его нужно приводить как точку отсчёта.

**P7 — Частичное вознаграждение.** При k проблемах, m true positive и f false positive:
`F1 = 2m / (m + k + f)`. Примеры (0 шагов проверки): k=3: m=1, f=0 → 0.00; m=2 → 0.60; m=3 → 1.00;
m=3, f=1 → 0.71. Вывод либо полностью верен (тип, точное множество идентификаторов, сумма в пределах τ,
валюта, полный набор доказательств), либо ничего не стоит; частичного вознаграждения *внутри* вывода нет.
По официальным определениям проверок τ = 0 по умолчанию, а идентификаторы сравниваются точно (на этапе P6
было τ = 1 и нормализованные идентификаторы; см. `p6_official_compliance_audit.md`; исправлено в ENV
0.2.0).

## 4. Пространство действий

`A = ⋃_κ {κ} × Θ_κ(h_t)`, κ ∈ {list, get, doc, calc, submit}. Области аргументов зависят от истории:

* `Θ_list = Tables(4) × Cursor(h_t) × {1..50}` — курсоры — это токены, возвращённые предыдущими
  страницами.
* `Θ_get = Tables × Ids(h_t) ∪ FxKeys` — идентификаторы нужно было увидеть; ключи курса можно построить из
  публичных дат и валют.
* `Θ_doc = DocIds(h_t)`.
* `Θ_calc = L(grammar)` — любая арифметическая строка.
* `Θ_submit` — множества до 30 выводов, каждый `(type, S_aff ⊆ Ids, amount ∈ ℕ, currency,
  S_ev ⊆ Ids ∪ FxKeys, text)`.

Оценка порядка величины (не измерение): в эпизоде medium с примерно 950 идентификаторами, на которые можно
сослаться, равномерно случайный вывод о дубле должен выбрать правильную пару среди ~10³–10⁴ пар счетов,
правильную сумму и полный набор доказательств из 3 идентификаторов среди ~10⁸ троек — вероятность успеха
намного ниже 10⁻¹². Ненаправленное исследование `Θ_submit` не может найти награду; это главное препятствие
для RL с нуля.

## 5. Исследовательские задачи

| № | задача | как проявляется в Ophanim | следствие |
|---|---|---|---|
| 1 | Последовательный сбор информации | каждый шаг раскрывает до 50 записей за 0.002 | при официальной награде доминируют дешёвые полные обходы (P3); для изучения сбора информации нужны режимы дефицита (только для исследований, на стороне агента) |
| 2 | Частичная наблюдаемость | непрочитанные записи | разрешима; явная память делает убеждение точным (P1) |
| 3 | Редкая итоговая награда | одна награда за эпизод | длинный горизонт до единственного сигнала |
| 4 | Распределение заслуг (credit assignment) | награда зависит от всего отправленного *множества* и от более ранних чтений | официальная награда не даёт заслуги по отдельным выводам; при обучении нужна факторизация или вспомогательные сигналы с учителем |
| 5 | Эпизоды переменной длины | 2–100 шагов; размеры таблиц меняются от эпизода к эпизоду | маски и кодировщики множеств, а не векторы фиксированной длины |
| 6 | Структурированные параметризованные действия | §4 | нужен адаптер действий (указатель или выбор кандидата) |
| 7 | Предсказание с ограничением на доказательства | для TP нужен полный набор доказательств из существующих идентификаторов | доказательства собираются из *раскрытых* записей и никогда не генерируются |
| 8 | Ограниченный бюджет | 100 шагов, 60 с, 0.002 за шаг | сегодня бюджет редко становится ограничением (P3) |
| 9 | Обобщение | невиданные seed, профили, комбинации, представление | проверять на отложенных профилях и комбинациях и на метаморфных вариантах; процедурная генерация даёт неограниченно много обучающих данных |

## 6. Формальная постановка задачи (для исследовательских документов)

Дан эпизод из `ρ(seed, config, secret)`. Агент взаимодействует не больше H = 100 шагов с детерминированным
набором инструментов только для чтения над статичным публичным набором данных `D` и сам хранит память о
раскрытых записях `K_t`. Он должен завершить эпизод множеством `F` структурированных выводов, идентификаторы
и доказательства которых взяты из раскрытых записей. Ответ оценивается один раз фиксированным взаимно
однозначным matcher относительно скрытого `Y* = g(D)` по формуле `R = clip(2·F1 − 1 − 0.002·k, −1, 1)`.
Цель обучения — максимизировать `E_ρ[R]` на отложенных распределениях эпизодов, а исследовательские
метрики (`p6_experiment_protocol.md`) разделяют **эффективность сбора информации** и **точность построения
выводов**.
