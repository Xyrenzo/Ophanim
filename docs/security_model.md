# Модель безопасности и изоляции

Цель: агент не должен получить скрытый ответ (эталон, provenance, seed, секрет, диагностику оценщика) и не
должен влиять на оценщик никаким способом, кроме отправки выводов.

## Модель угроз

**Что защищаем:** эталон (`truth.json` и его копия в памяти судьи), provenance, seed закрытого набора,
секрет `OPHANIM_EVAL_SECRET`, журнал судьи и траекторию oracle.

**Кому доверяем:** процессу оценщика (генератор, окружение, судья, верификатор) и коду OPHANIM.

**Кому не доверяем:** политике агента — любому коду, который мы не писали. Считаем, что она может
выполнять произвольные действия от имени того пользователя, под которым запущена, читать файлы, перебирать
seed, писать в stdout мусор и бесконечные строки, зависать и падать.

| канал | угроза | защита | статус |
|---|---|---|---|
| протокол stdin/stdout | недопустимые сообщения, огромные строки, поток вывода | невалидное сообщение становится одним `invalid_action`; строка длиннее 1 МБ не держится в памяти (дочитывается и отбрасывается); весь вывод агента ограничен 16 МБ на эпизод, дальше агент обрывается (`agent_output_limit`); запись в агента идёт в отдельном потоке | реализовано, `tests/security/` |
| время | зависание агента | лимит 60 с от `reset`, после него процесс агента убивается, ответ считается пустым | реализовано |
| наблюдения и ошибки | утечка эталона через ответы инструментов | инструменты построены только из публичных таблиц; коды и тексты ошибок фиксированы; в закрытом режиме награда 0.0 | реализовано, проверки утечек в `verify` |
| переменные окружения | секрет и токены хоста в окружении агента | агент получает окружение по белому списку (`PATH` и то, что нужно интерпретатору), без `OPHANIM_*` и без любых других переменных хоста; `PYTHONHASHSEED=0` | реализовано |
| `/proc/<оценщик>/environ`, `mem`, `maps` (Linux) | агент того же пользователя читает окружение оценщика с секретом | оценщик помечает себя non-dumpable (`prctl(PR_SET_DUMPABLE, 0)`) перед запуском агентов. Проверено в Linux-контейнере: без этого дочерний процесс читал `OPHANIM_EVAL_SECRET`, с ним получает `PermissionError` | реализовано для непривилегированного пользователя; root эту защиту обходит |
| `/proc/<оценщик>/cmdline` (Linux) | скрытый seed base, переданный аргументом `--seed-base` | `cmdline` читается всеми; передавайте seed base через `OPHANIM_SEED_BASE` | рекомендация |
| файловая система | чтение файлов эталона, кода оценщика, отчётов | эталон закрытого прогона существует только в памяти; отчёты пишутся после всех агентов; рабочий каталог агента пуст. Отдельный процесс всё равно видит всё, что доступно пользователю (открытые train/dev, исходники) | частично; полностью — только в контейнере |
| память оценщика (Windows) | процесс того же пользователя может читать память другого процесса | средствами Python не закрывается | остаточный риск; используйте контейнер |
| перебор seed | агент перегенерирует закрытые эпизоды открытым генератором | вся генерация закрытого прогона подписана `HMAC-SHA256(секрет, seed)`, `episode_id` выводится из ключа (`test_secret_defeats_seed_brute_force`) | реализовано |
| сеть | выгрузка данных, внешняя помощь | у процесса агента сеть хоста; в контейнере сети нет (`--network none`) | только в контейнере |
| ресурсы | исчерпание памяти, CPU, процессов | в контейнере: `--memory`, `--memory-swap`, `--cpus`, `--pids-limit`; у отдельного процесса — только лимит времени | только в контейнере |
| повышение привилегий | setuid-бинарники, capabilities | в контейнере: `--cap-drop ALL`, `--security-opt no-new-privileges`, пользователь 65534 | только в контейнере |

## Границы

| уровень | что доступно агенту | что недоступно |
|---|---|---|
| Инструменты (`env/tools.py`) | копии публичных таблиц и документов только для чтения | эталон, provenance, seed, генератор, судья (набор инструментов строится только из публичных таблиц) |
| Наблюдения | запрошенные записи, результат или код ошибки, оставшиеся шаги | идентификаторы проблем, ожидаемые суммы, детали сопоставления, награда (в закрытом режиме) |
| Ошибки | фиксированный код и фиксированное сообщение (ввод не повторяется, без трассировок стека и путей) | внутреннее состояние |
| Процесс | в закрытой оценке агент — отдельный процесс ОС, общающийся через JSON lines (`agent_runtime.py`) | объект окружения, судья, эталон в памяти |
| Переменные окружения | минимальный набор по белому списку и `PYTHONHASHSEED=0` | секрет оценки, токены и прочие переменные хоста |
| Рабочий каталог | пустой временный каталог, он же `HOME` и `TMP`; удаляется после эпизода | выходные файлы оценщика (они пишутся только после завершения всех агентов) |

## Два режима запуска агента

**Отдельный процесс** (по умолчанию в `ophanim evaluate` и `run-agent`). Работает везде без Docker. Это
граница процесса, а не песочница: агент работает от того же пользователя, видит ту же файловую систему и
сеть хоста. Подходит для своих и проверенных политик.

**Контейнер на каждого агента** (`ophanim run-agent --container IMAGE`,
`process_runner.container_agent_command`). Команда запускает одноразовый контейнер с флагами:
`--network none`, `--read-only`, `--cap-drop ALL`, `--security-opt no-new-privileges`,
`--user 65534:65534`, `--ipc none`, `--pids-limit 64`, `--memory 512m --memory-swap 512m`, `--cpus 1`,
маленький `/tmp` с `noexec,nosuid`, `--log-driver none`, без томов и без Docker-сокета хоста. После эпизода
контейнер удаляется (`remove_container`), даже если агент завис. Образ `docker/agent.Dockerfile` содержит
только код агента: в нём нет `data/`, конфигураций, тестов, генератора и оценщика.

Проверено вручную на этой машине (Docker Desktop, Linux-контейнеры): внутри контейнера uid 65534,
`CapEff = 0`, `NoNewPrivs = 1`, виден только собственный PID 1, корневая файловая система только для
чтения, сетевое соединение невозможно, каталогов с данными и кода оценщика нет; эпизод через
`run-agent --container` проходит, как и в режиме процесса.

Чего контейнер не даёт: защиты от уязвимостей ядра (контейнер делит ядро с хостом) и гарантий при
неверной настройке самого Docker. Для по-настоящему враждебного кода нужен изолятор уровня ядра (gVisor,
Kata Containers, Firecracker) или отдельная виртуальная машина. Флаг `--network none` сам по себе изоляцией
не является — важна вся совокупность флагов выше и содержимое образа.

## Конкретные угрозы и защита

* **Перебор seed.** Генератор открыт. Если скрытые seed небольшие, агент мог бы перегенерировать
  кандидатов и прочитать ответ. Поэтому в закрытых прогонах вся генерация подписывается ключом
  `HMAC-SHA256(OPHANIM_EVAL_SECRET, seed)`, а `episode_id` выводится из этого ключа, а не из исходного seed.
  Проверено: без точного секрета не совпадают ни идентификаторы, ни данные
  (`test_secret_defeats_seed_brute_force`).
* **Структурные подсказки.** Публичные идентификаторы — случайные токены из потока представления, который
  не зависит от содержания и ошибок; порядок записей применяется после внесения ошибок; каждая сигнатура
  ошибки (строки Suspense, даты со сдвигом UTC, одинаковые суммы, одинаковые `vendor_ref`, строки курсовых
  разниц) встречается и в чистых книгах как законная операция. Проверено: внесённые копии равномерно
  распределены по рангу идентификатора; в чистых книгах есть все виды ложных следов
  (`tests/integration/test_red_herrings.py`).
* **Злоупотребление калькулятором.** Токенизатор и парсер написаны вручную; допустимы только числа из
  цифр ASCII с десятичной точкой и `+ - * / ( )`; нет `eval`, `exec`, `ast`, имён, вызовов, степеней,
  экспоненциальной записи и цифр Unicode; есть ограничения длины, глубины, числа цифр и величины. AST-проверка
  всего кода запрещает `eval/exec/compile/__import__`.
* **Враждебные процессы агентов.** Некорректный JSON, сообщения не в виде объекта и строки длиннее 1 МБ
  становятся невалидными действиями; строки читаются кусками, так что длинная строка без перевода строки не
  раздувает память оценщика; агент, выдавший больше 16 МБ, обрывается; упавший или не отвечающий агент
  прерывается по лимиту времени и оценивается как пустой ответ; запись в агента идёт в отдельном потоке,
  поэтому агент, который не читает ввод, не может заблокировать оценщик
  (`tests/security/test_isolation_hardening.py`).
* **Подмена награды и запись в оценщик.** Ни один инструмент ничего не записывает; `submit` — единственный
  вход для оценки; первый `submit` завершает эпизод; повторные игнорируются.
* **Утечки через журналы.** Публичные траектории содержат только то, что видел агент; журналы судьи,
  траектория oracle и отчёты предназначены только оценщику и пишутся после прогонов агентов. Проверка
  утечек в каждой опубликованной траектории выполняется в `ophanim verify`. Локальные результаты
  `evaluate` в каталоге `artifacts/` исключены из Git (`.gitignore`) и из контекста сборки Docker
  (`.dockerignore`).
* **Испорченная история эпизода.** Верификатор воспроизводит цепочку «чистые книги → внесённые ошибки →
  опубликованные книги» по provenance и требует точного совпадения; любая нестыковка — ошибка верификации
  (`evaluator/provenance_check.py`, `tests/integration/test_provenance_chain.py`).

## Oracle

`evaluator/oracle.py` читает закрытый эталон и находится только в пакете оценщика. Он никогда не
регистрируется как политика агента (`policies/` не может импортировать код оценщика — это проверяет
AST-тест) и никогда не запускается как процесс агента. В отчётах абляций он помечен как «evaluator-only».

## Остаточные риски

* В режиме отдельного процесса агент делит файловую систему и сеть с пользователем и может прочитать
  доступные ему файлы. Эталон закрытого прогона во время прогона существует только в памяти оценщика;
  файлы эталона *открытых* train/dev лежат на диске по замыслу. Для недоверенного кода используйте
  контейнерный режим.
* Защита `/proc` через `PR_SET_DUMPABLE` работает только в Linux и только против непривилегированного
  пользователя; в Windows память процесса другим процессом того же пользователя не защищается.
* Контейнер делит ядро с хостом; это не защита от эксплойтов ядра.
* Внутрипроцессный `OphanimEnv` (для обучения, тестов и абляций) держит судью в том же процессе Python; он
  предназначен для открытого обучения и измерений, а не для состязательной закрытой оценки.
* Лимит 60 секунд по настенным часам — единственный недетерминированный элемент эпизода.
